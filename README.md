Built with Node.js and Express, this tool offers a user-friendly interface to fetch content in various formats and qualities, leveraging `ytdl-core` for efficient stream retrieval and `ffmpeg` for powerful media processing. ## 🏗️ Architecture

The application follows a client-server architecture, where the Node.js Express server acts as the backend, handling all YouTube interactions and media processing, while the EJS-rendered HTML provides the user interface.

```mermaid
graph TD
    A["User"] --> B["Web Browser"];
    B -- "GET /" --> C["Node.js Express Server"];
    C -- "Renders index.ejs" --> B;
    B -- "POST /download (YouTube URL, Format, Quality)" --> C;
    C -- "Uses ytdl-core" --> D["YouTube Servers"];
    D -- "Video/Audio Stream" --> C;
    C -- "Processes Stream (ffmpeg)" --> E["Processed Media Stream"];
    E -- "Sends Downloadable File" --> B;
```

**Detailed Flow:**

1.  **User Interaction:** A user accesses the web application through their browser.
2.  **Initial Page Load:** The browser sends a `GET` request to the Node.js Express server, which responds by rendering the `index.ejs` template, presenting the main download interface.
3.  **Download Request:** The user inputs a YouTube video URL, selects their desired format (MP4/MP3) and quality, and submits the form. This triggers a `POST` request to the `/download` endpoint on the Express server.
4.  **YouTube Stream Retrieval:** The Express server utilizes the `ytdl-core` library to interact with YouTube's servers. It fetches metadata and initiates a stream for the requested video/audio content.
5.  **Media Processing:** The incoming stream from YouTube is then piped to `fluent-ffmpeg`.
    *   If an MP4 video download is requested, `ffmpeg` might remux the audio and video streams into a single MP4 container, or simply pass through the stream if it's already in a suitable format.
    *   If an MP3 audio download is requested, `ffmpeg` transcodes the video stream into an audio-only MP3 format.
6.  **File Delivery:** Once `ffmpeg` has processed the stream, the Node.js server sets appropriate headers (`Content-Disposition`, `Content-Type`) and streams the processed media directly back to the user's browser, initiating the file download.

## 🚀 Getting Started

Follow these instructions to get a copy of the project up and running on your local machine for development and testing purposes.

### Prerequisites

Before you begin, ensure you have the following installed:

*   **Node.js:** Version 18 or higher.
    *   [Download Node.js](https://nodejs.org/en/download/)
*   **npm:** Node Package Manager (comes with Node.js).
*   **Git:** For cloning the repository.
    *   [Download Git](https://git-scm.com/downloads)
*   **Docker (Optional, for Docker Installation):**
    *   [Download Docker Desktop](https://www.docker.com/products/docker-desktop/)

### Local Installation

1.  **Clone the repository:**
    ```bash
    git clone https://github.com/Can-Ozan/Youtube-Downloader-Pro-v6.0.git
    cd Youtube-Downloader-Pro-v6.0
    ```

2.  **Install dependencies:**
    ```bash
    npm install
    ```

3.  **Start the server:**
    ```bash
    npm start
    ```
    The application will be running on `http://localhost:3000`.

### Docker Installation

For a containerized and isolated environment, you can use Docker.

1.  **Clone the repository:**
    ```bash
    git clone https://github.com/Can-Ozan/Youtube-Downloader-Pro-v6.0.git
    cd Youtube-Downloader-Pro-v6.0
    ```

2.  **Build the Docker image:**
    This command builds a Docker image named `youtube-downloader-pro` from the `Dockerfile` in the current directory.
    ```bash
    docker build -t youtube-downloader-pro .
    ```
    *   The `Dockerfile` first sets the base image to `node:18-alpine`, a lightweight Node.js environment.
    *   It then installs `ffmpeg` and `ca-certificates` which are crucial for media processing and secure connections.
    *   The working directory is set to `/app`.
    *   `package.json` and `package-lock.json` are copied, and `npm install` is run to install dependencies.
    *   Finally, the rest of the application code is copied, and the default command `npm start` is defined to run the application.

3.  **Run the Docker container:**
    This command runs a new container from the `youtube-downloader-pro` image.
    ```bash
    docker run -p 3000:3000 --name youtube-downloader-app youtube-downloader-pro
    ```
    *   `-p 3000:3000`: Maps port `3000` on your host machine to port `3000` inside the container. This allows you to access the application via `http://localhost:3000`.
    *   `--name youtube-downloader-app`: Assigns a memorable name to your container, making it easier to manage.
    *   `youtube-downloader-pro`: Specifies the Docker image to use.

4.  **Access the application:**
    Open your web browser and navigate to `http://localhost:3000`.

**Useful Docker Commands:**

*   **Stop the running container:**
    ```bash
    docker stop youtube-downloader-app
    ```
*   **Remove the container:**
    ```bash
    docker rm youtube-downloader-app
    ```
*   **Remove the image:**
    ```bash
    docker rmi youtube-downloader-pro
    ```
*   **View running containers:**
    ```bash
    docker ps
    ```
*   **View all containers (including stopped):**
    ```bash
    docker ps -a
    ```

## 🏗️ Architecture

The YouTube Downloader Pro v6.0 operates on a classic client-server model, where the Node.js Express server acts as the central processing unit, handling all interactions with YouTube and performing media conversions. The client-side, rendered by EJS, provides the user interface for initiating downloads.

```mermaid
graph TD
    A["User"] --> B["Web Browser"];
    B -- "1. GET / (Request Main Page)" --> C["Node.js Express Server"];
    C -- "2. Renders index.ejs" --> B;
    B -- "3. POST /download (YouTube URL, Format, Quality)" --> C;
    C -- "4. Uses ytdl-core to fetch stream info" --> D["YouTube Servers"];
    D -- "5. Streams Video/Audio Data" --> C;
    C -- "6. Processes Stream (fluent-ffmpeg)" --> F["Processed Media Stream"];
    F -- "7. Sends Downloadable File" --> B;
```

**Detailed Architectural Flow:**

1.  **Client Request (Initial Load):** The user initiates interaction by navigating to the application's URL in their web browser. This sends a `GET` request to the root endpoint (`/`).
2.  **Server-Side Rendering:** The Node.js Express server receives the `GET` request. It then uses EJS to render the `index.ejs` template, which forms the main user interface for the downloader. This rendered HTML, along with associated CSS and JavaScript, is sent back to the client's browser.
3.  **User Input & Download Request:** On the `index.ejs` page, the user pastes a YouTube video URL and selects their desired download options (e.g., MP4 video, MP3 audio, specific video quality). Upon submission, the browser sends a `POST` request to the `/download` endpoint of the Express server, including the YouTube URL and selected options as payload.
4.  **YouTube Interaction (Metadata & Stream Fetch):** The Express server, upon receiving the `POST` request, utilizes the `ytdl-core` library. `ytdl-core` communicates with YouTube's servers to retrieve detailed information about the video (available formats, qualities, etc.) and then establishes a stream to download the selected content directly.
5.  **Media Processing with FFmpeg:** The raw video/audio stream from YouTube is piped directly into `fluent-ffmpeg`.
    *   If the user requested an **MP4 video**, `ffmpeg` efficiently remuxes the separate audio and video streams (if they are separate) into a single MP4 container, ensuring proper synchronization.
    *   If the user requested an **MP3 audio**, `ffmpeg` transcodes the video stream into an audio-only MP3 format, applying necessary audio encoding.
6.  **File Delivery to Client:** After `ffmpeg` completes its processing, the Node.js server sets appropriate HTTP headers (`Content-Disposition` for filename, `Content-Type` for media type) and streams the final processed media file back to the user's browser. This action prompts the browser to initiate a file download for the user.

This architecture ensures that the heavy lifting of stream processing and conversion is handled server-side, providing a smooth and efficient experience for the user
